# LoGoPlanner 框架详解与答疑

> 论文:**LoGoPlanner: Localization Grounded Navigation Policy with Metric-aware Visual Geometry**(arXiv 2512.19629v2)
> 配套流程图:[2512.19629v2_LoGoPlanner_core_framework.drawio](2512.19629v2_LoGoPlanner_core_framework.drawio)

---

## 一句话概括

LoGoPlanner 把**定位 + 度量几何感知 + 轨迹规划**三件事塞进**一个可端到端训练的策略网络**。输入只有 **RGB-D 历史观测**和**一个点目标**,**不依赖任何外部 SLAM / VO / 精确的相机-底盘外参**。

核心主线:

```
RGB-D + 点目标
  → [度量几何骨干] 融出带真实米制尺度的 metric token
  → [辅助分支]     逼出隐式特征 hᶜ(定位)/ hᵖ,hʷ(几何)   ← 训练时用点云/外参监督
  → [策略]         query 去"问"这些隐式特征 + 目标 → 规划上下文
  → [扩散头]        K 步去噪 → 避障动作序列
```

**两个最值得记住的 idea:**
1. **度量感知**——用深度尺度先验给视觉几何骨干注入真实米制尺度;
2. **定位锚定但隐式传递**——定位/几何在训练时被监督学好,推理时以**隐式特征**而非显式 pose/点云传给规划器,从根上避免误差级联,也摆脱对外部定位与精确标定的依赖。

# 第一部分:框架分阶段详解

## 1、论文动机:现有导航范式的瓶颈

解释现有两类方法的死穴,引出切入点。

| 范式 | 做法 | 死穴 |
|------|------|------|
| **显式模块化规划器** | 感知→定位→建图→规划,一环扣一环 | **误差级联**:上游错一点下游全盘皆输;腿式平台相机/IMU 抖动进一步放大定位建图误差 |
| **当前端到端规划器** | 观测直接出轨迹 | 大多仍**偷偷依赖 SLAM/VO/oracle 定位**更新自状态,且要求**精确相机-底盘外参**,换平台要重标定 |

**LoGoPlanner 的切入点**:把定位、度量几何记忆、规划**统一进一个可训练策略**。核心理念——**不把上游显式 pose/点云直接喂给规划器**,而是通过**隐式特征 + query 交互**传递,在源头切断误差传播。这个"隐式而非显式"的思想贯穿全文。

## 2、输入与问题形式化

**输入只有两样:**
1. **历史 RGB-D 序列**:每帧 = RGB 图像(语义、颜色)+ 深度图(近距离几何)。用历史序列是为了有时间上下文、能推断自运动。
2. **点目标**:一个三维坐标点(相对出发点的偏移,详见答疑 Q1/Q2)。

**要输出的四类东西**(也是后面各分支各自的监督目标):
- 度量底盘位姿(metric chassis pose)——我在哪、朝哪;
- 相对目标(relative goal)——目标相对我在哪;
- 稠密局部/世界点云——周围环境几何;
- 避障轨迹(trajectory)——最终执行的动作。

## 3、Metric-aware Visual Geometry Learning(度量感知视觉几何 / 感知骨干)

解决老大难问题:**纯视觉几何没有绝对尺度**——看得出远近关系,说不出真实米数,而导航必须要米制。

- **RGB → ViT-L 编码器** → 语义 token(理解"墙/门/人");
- **Depth → ViT-S 尺度先验编码器** → 几何 token(带真实距离);
- 两路在 **patch 级用带 RoPE 位置编码的注意力融合** → **度量几何 token(metric token)**。

底层挂着**预训练的 video geometry backbone(VGGT)**,提供长时序、多帧一致的几何表征;通过后训练微调**对齐到绝对米制尺度**(详见答疑 Q3)。metric token 是后面所有分支的共同输入。

## 4、辅助监督分支:把定位与几何变成可学习的隐式特征

全框架最巧妙处。**不直接用几何/定位结果去规划**,而是把它们做成**辅助监督任务**,逼网络在中间层学出高质量隐式特征 `hᵖ / hᶜ / hʷ`:

| 分支 | 产出隐式特征 | 解码/监督 |
|------|------|------|
| **Local Point Head** | 局部点特征 **hᵖ** | 解码相机系局部点云;监督来自深度 + 针孔模型算的真值局部点 |
| **Pose Head** | 位姿特征 **hᶜ** | 解码相机外参、底盘位姿,把全局目标转成底盘系相对目标;专学**跨高度/俯仰角/平台**的自定位 |
| **World Point Fusion** | 世界点特征 **hʷ** | 融合 hᵖ+hᶜ,经指数尺度映射解码稠密世界点云,统一对齐到**最后一帧底盘系** |

**要点**:这些点云/外参在**训练时**用作监督(让特征学得好),但**推理规划时不显式使用其解码结果**——真正往下游传的是 `hᶜ / hᵖ / hʷ` 三组隐式特征。这就是"避免误差级联"的具体落地。

## 5、Localization Grounded Navigation Policy(规划核心)

规划器不吞点云和 pose,而是用 **query 去"问"上一阶段的隐式特征**:

- **State Query**:状态 query 对**位姿特征 hᶜ**做交叉注意力 → 隐式自状态/定位表征;
- **Geometric Query**:几何 query 对**局部/世界点特征 hᵖ/hʷ**做交叉注意力 → 隐式环境几何与障碍关系;
- **Goal Encoder**:把点目标编码成 goal embedding 作为目标约束。

三者送入 **Transformer Decoder** 拼成**规划上下文(planning context)**。核心设计:规划器**只消费隐式的状态/几何条件,不显式串联上游 pose/点云**,降低误差级联。

**Diffusion Policy Head(扩散策略头)**:从高斯噪声出发,以规划上下文为条件,**迭代 K 步逐步去噪**,输出干净动作序列,每步 (Δx, Δy, Δθ)。用扩散是因为导航动作分布常是**多模态**的(左绕/右绕都对),扩散能建模这种多解性。

## 6、推理输出与部署收益

- **输出轨迹**:底盘系下的未来动作序列,目标是可执行、避障、向目标收敛。
- **部署特点**(整个设计换来的实惠):
  - 不需要外部 SLAM/VO;
  - 不要求精确相机-底盘外参;
  - 对不同机器人高度、相机俯仰角、真实场景有泛化能力;
  - metric geometry memory 提升避障稳定性。

## 7、训练范式与监督信号(两阶段)

| 阶段 | 做什么 | 监督/设置 |
|------|------|------|
| **Stage 1:几何/定位后训练** | 微调 video geometry decoder + 各任务头,注入深度尺度先验 | 监督 = 米制场景点云 + 相机外参;随机化机器人高度 **0.25–1.25m**、相机俯仰角 **0–30°**(跨平台泛化的直接来源);batch 12,24 小时 |
| **Stage 2:规划联合训练** | **冻结骨干 decoder**,联合训扩散头 + 任务头 | 以**轨迹规划误差**为最终优化目标;稳住状态估计、保住感知;batch 32,3 天 |

**辅助任务消融结论**:里程计增强自运动估计、目标任务做动态目标对齐、点云任务捕获 2D 语义之外的空间障碍关系;三者叠加后 Home SR/SPL = **57.3/52.4**,Commercial = **67.1/63.9**。

## 8、关键结果

- **仿真(未见场景)**:Home SR 57.3 / SPL 52.4,Commercial SR 67.1 / SPL 63.9;相比**用了 oracle 定位**的 ViPlanner,Home 场景 SR 提升 **27.3 个百分点**、SPL 提升 **21.3 个百分点**——**没用真值定位反而更强**,证明隐式定位路线有效。
- **真实机器人**:TurtleBot 办公室 **85%**、宇树 Go2 家居 **70%**、宇树 G1 工业 **50%**;跨平台、跨场景、跨视角,**全程不依赖外部定位模块**。

# 第二部分:关键问题答疑

## Q1. 点目标那个 3D 坐标的来源是什么?

**本质:任务给定的外部目标,不是网络算出来的。**

LoGoPlanner 做的是 **point-goal navigation**,目标 g ∈ R³ 是"designated target point"——**由任务/上层系统直接指定**的目的地,是问题的**输入条件**,不是从图像估计的。它表达在**以出发点为原点**的参考系里,即"目标相对起点的偏移"。

- **训练时**:仿真里**随机采样 start–goal 配对**(都在可通行区、距离 **4–10m**),再用 **A\*** 生成路径 → 贪心细化 → 三次样条平滑,得到无碰撞专家轨迹。全数据集 20 万+ 轨迹、约 1000 万渲染图。
- **部署时**:由用户/上层规划器给出"去某坐标"。

**关键的坑**:全局 g **不能直接用**,要不断投影成相对目标。网络先从视觉历史估计自状态 ŝ₁:ᵢ,再把 g 变换到当前坐标系,得到 **ĝᵢ = f(ŝ₁:ᵢ, g)**。对应流程图:**Pose Head(hᶜ 隐式自定位)→ 投影 g → Goal Encoder**。

## Q2. 没有定位,如何给出到目标点的 3D 坐标?

**破题点:"没有定位"到底指没有什么。**

坐标必须依附于参考系没错,但——**这个目标坐标是以"出发点"为原点、在起始时刻一次性给定的**。t=0 时机器人自身坐标系就是参考系,"目标坐标"本质是一句**相对位移**:"从我现在位置和朝向算起,目标在前方 6m、左侧 2m"。给出它**零定位需求**。

**真正需要"定位"的不是起点,而是之后每一步**:机器人一动,当前坐标系就和起点不重合,必须知道"我移动/转动了多少"才能更新相对目标。

- **传统做法**:靠外部里程计/VO/SLAM(iPlanner、ViPlanner 用 ORB-SLAM3)累积自运动;
- **LoGoPlanner**:不挂外部模块,**从视觉历史隐式学出自运动**,持续把最初目标偏移重投影到当前帧。

所以"没有定位"是精确到含义的:

| 类型 | LoGoPlanner |
|------|------|
| 外部/绝对定位模块(SLAM、VO、仿真真值 pose) | ❌ **完全不用**——标榜的卖点 |
| 相对自运动估计(odometry) | ✅ **需要,但在网络内部隐式完成**,由 Pose Head + 里程计辅助任务学出 |

**一句话**:目标坐标不需要定位就能给,是因为它**从一开始就是"相对出发点"的偏移量**;起点时机器人自身即原点,天然成立。需要"知道自己在哪"的是移动后如何持续更新相对目标,而这一步被**网络内部隐式估计的自运动**替代了外部定位模块。

## Q3. 底层"预训练 video geometry backbone + 微调对齐米制"详解

**这段在回答:怎么让机器人从普通 RGB 视频里看出带真实米数的三维几何。**

### 1) backbone 是什么
用的是 **VGGT**(Visual Geometry Grounded Transformer)这类**视频几何模型**(同类还有 Video Depth Anything)。它是**预训练好的前馈网络**:喂进图像序列,一次前馈同时吐出**稠密深度、三维点、每帧相机外参**。

### 2) "预训练"给了两样能力
靠**交替注意力(alternating attention)**:
- **帧内注意力** → 单帧几何细节清晰(局部保真);
- **帧间注意力** → **跨帧几何互相对齐一致**(long-horizon consistency),同一堵墙在不同帧是同一个东西,不漂移。

对运动机器人至关重要——要的是**稳定连贯的环境几何记忆**,顺带给出每帧相机位姿(隐式自定位的地基)。

### 3) 致命短板:只有"相对尺度"
纯视觉几何有**尺度不确定(scale ambiguity)**:形状对,但整体可任意缩放——说不出"墙在 4.6m 还是 46cm"。而规划必须在**真实米制**下做,所以预训练骨干**不能直接用**。

### 4) 后训练微调:用深度当尺度锚
把**深度图作为尺度先验注入骨干**再微调:
1. **RGB → ViT-L** → 语义 token tᴵ(有相对几何、无绝对尺度);
2. **Depth → 轻量 ViT-S** → 几何 token tᴰ(深度读数带真实米数,就是"标尺");
3. **patch 级 RoPE 注意力融合** → **度量感知 token tᵐᵉᵗʳᶦᶜ**。

直观理解:VGGT 给"会缩放的正确形状",深度给"到底几米",一融合就把相对尺度**钉死到绝对米制**。世界点云解码还用指数映射 `P = sign(z)·(exp|z|−1)` 增强大坐标表达力、避免饱和。

### 5) 为什么非要"多帧"
单帧深度**噪声大、量程有限、有 sim-to-real 差距、无时间一致性**(iPlanner/ViPlanner 单帧输入正是被批评点)。所以**分工**:video 骨干出"连贯形状 + 位姿",深度出"绝对尺度",合起来才是"**多帧一致 + 真实米制**"。

### 6) 后训练落在哪
即 **Stage 1**:微调 video geometry decoder + 任务头,监督 = 米制场景点云 + 相机外参 → 完成"对齐绝对米制"。**Stage 2** 冻结骨干,专注规划。

**一句话**:底层 VGGT 是**预训练好、能从视频前馈重建三维几何+相机位姿的模型**,强在**多帧一致的连贯几何**,但天生只有**相对尺度**;LoGoPlanner 把**带真实米数的深度当尺度先验编码融入、并微调骨干 decoder**,把"会缩放的几何"**锚定成绝对米制点云**,得到既**多帧一致**又**真实米制**的几何表征供下游使用。

## Q4. 辅助监督分支详解:把定位与几何"逼"成隐式特征

**核心细节:这三个头的解码输出(点云、位姿)只是"训练用的靶子",推理时被丢弃;真正往规划器传的是它们中间层挤出来的隐式特征 hᵖ/hᶜ/hʷ。**

### 1) 为什么要辅助监督(反面证据)
消融显示:若**完全不加辅助任务**、只用端到端轨迹监督,模型只有**基础路径规划能力**,"intermediate features lack explicit guidance",自状态一旦估偏就**跟丢目标**。所以要在中间层加监督,**强行把定位/几何含义塞进隐式特征**——这就是"逼"字的由来。

### 2) 三个头分别做什么

**① Local Point Head——局部点预测(细粒度几何)**
- 从度量 token 提取局部点特征 **hᵖ**,解码出相机系下一组局部三维点。
- 监督靶子:用**针孔模型**把每像素反投影 `点(u,v) = 深度D × K⁻¹[u,v,1]ᵀ`(K 为内参)。
- 关键:**不直接拿带噪深度投影,而让网络预测**——"data-driven prediction improves reconstruction robustness",目的不是那堆点,而是挤出干净特征 hᵖ。

**② Camera Pose Head——相机/底盘位姿(定位+里程计+目标)**
- 痛点:感知在**相机系**、控制在**底盘系**,跨平台时相机高度/俯仰角一变就错位;传统靠**精确标定外参**又脆又不泛化。
- 做法:**解耦**相机位姿与底盘位姿为两个独立任务,用隐式特征桥接、**不做显式标定**(假设相机相对底盘无 yaw)。
- 从位姿特征 hᶜ 同时解码三样:
  - 相机→世界变换 Tc(相机位姿);
  - 底盘位姿 Tb = `(x, y, θ)`,x,y 相对起点、θ 偏航 —— 即**里程计/ego-motion**;
  - 相对目标 ĝᵢ = fg(hᶜ, g) —— 全局目标投影到当前系。
- 相机与底盘关系 `Tc = Tb · Text`,Text 是**固定外参**,只编码相机相对底盘的高度和俯仰角;训练时在**任意高度/俯仰角**下构造数据 → 跨本体泛化。

**③ World Point Fusion——世界点预测(几何记忆聚合)**
- 原话:"Rather than directly encoding the predicted local points or poses, we exploit their **intermediate task-specific features**"。
- 把局部点特征 hᵖ + 位姿特征 hᶜ **拼接**,经上下文融合模块 A 跨 patch 聚合 → 世界点特征 **hʷ**;解码出米制稠密世界点云(指数映射 `sign(z)·(exp|z|−1)` 防饱和)。
- 坐标**统一到最后一帧底盘系**,与规划坐标系对齐 —— 把多帧局部几何 + 自运动融成一份**场景级、真实米制的几何记忆**。

### 3) "逼成隐式特征"到底是什么意思(本阶段核心)
解码输出是训练靶子、推理时丢弃;真正传给规划器的是 hᵖ/hᶜ/hʷ。论文:"This strategy **avoids cascading errors** that would otherwise arise from **directly applying upstream predictions to downstream tasks**"。

| | 传统流水线 | LoGoPlanner |
|------|------|------|
| 传递内容 | pose/点云的**数值** | 中间**特征** hᵖ/hᶜ/hʷ |
| 后果 | pose 错→规划跟着错(级联) | query 从特征按需取用,容错强 |

辅助任务是**"教练"而非"数据通道"**——训练时逼特征学好,推理时只留特征、扔掉解码头。

### 4) 消融证据(Table III,逐步叠加)

| 加入的辅助任务 | Home SR/SPL | Commercial SR/SPL |
|------|------|------|
| 全不加(仅端到端) | 49.5 / 47.0 | 59.4 / 57.0 |
| + Odometry | 51.3 / 49.7 | 61.2 / 59.2 |
| + Goal | 52.4 / 50.1 | 63.3 / 60.3 |
| + Point Cloud(三者全上) | **57.3 / 52.4** | **67.1 / 63.9** |

各任务角色(消融任务名 ↔ 架构头的对应):
- **Odometry**(← Pose Head 底盘位姿):监督自运动估计;
- **Goal**(← Pose Head 相对目标):基于自状态动态更新目标,不跟丢;
- **Point Cloud**(← Local/World Point Head):把历史观测用估计外参转成几何点云,捕获 2D 语义之外的空间障碍关系,显著提升避障(SR 52→57)。

**一句话**:辅助分支用三个"训练时才存在"的头(局部点/相机-底盘位姿/世界点),以针孔点云、里程计、相对目标、米制点云为靶子,把定位与几何**逼进中间特征 hᵖ/hᶜ/hʷ**;推理时丢弃解码头,只用这三组隐式特征经 query 交互喂给规划器,从而既学到该学的、又避免"传数值"的误差级联。

## Q5. 深入 Local Point Head:预测什么、监督在比什么

Local Point Head 对应论文公式 (2)(3),负责"看懂当前帧、相机眼前的三维结构长什么样"(细粒度结构),与 Pose Head(长时程自运动)并列,都从同一度量 token 分叉。

### 1) 输入 / 输出
- 输入:第 3 阶段融合好的**度量 token t_metric**(带真实米制尺度)。
- `hᵖ = φp(t_metric)` 提取局部点特征 → `P_local = fp(hᵖ)` 解码出**相机坐标系下、逐帧的一组局部三维点**("canonical local 3D points",尚未拼进世界系)。

### 2) 监督到底"谁跟谁比"
一个**逐点回归损失**,比较双方是:

| | 内容 | 来源 |
|------|------|------|
| **预测点云 P̂_local** | 网络**猜**的局部点 = `fp(hᵖ)` | Local Point Head 从度量 token 解码 |
| **真值点云 P_cam** | 深度反投影的标准答案 = `D(u,v)·K⁻¹[u,v,1]ᵀ` | **仿真真值深度 D** + 相机内参 K |

即**"网络预测的点云" ↔ "深度反投影出的真值点云"**做逐点对齐(L1/MSE)。真值不是和深度图本身比、也不是和别的分支比,就是监督网络自己解码出的那组预测点。

针孔反投影直观理解:`K⁻¹[u,v,1]ᵀ` 把像素 (u,v) 变成一条从光心射出的**射线方向**,再乘深度 `D(u,v)` 沿射线走那么远 → 落到相机系三维点。逐像素做一遍得整帧真值点云。

### 3) 深度既是输入又当监督,循环吗?——不循环
- **输入端**:深度经 ViT-S 编成几何 token,只作**尺度先验**融进特征(提示);
- **监督端**:深度反投影成点云,作**重建标准答案**。

网络不是被要求"把输入深度原样吐回",而是**从融合特征里重建干净、鲁棒的三维点**。收益有二:① 直接反投影原始深度会把噪声/空洞/反光失效搬进点云,数据驱动预测能**去噪补洞**("data-driven prediction improves reconstruction robustness");② 训练这个任务时**把几何结构压进中间特征 hᵖ**,这才是下游真正要用的。仿真里深度干净能当好靶子,部署到真机深度变脏时,这个头已学会"输出比脏深度更好的几何"——泛化正体现于此。

### 4) 三分支监督靶子对照(避免混淆)

| 分支 | 预测什么 | 真值靶子 |
|------|------|------|
| **Local Point Head** | 相机系逐帧局部点 | **深度反投影的局部点云** |
| World Point Fusion | 统一世界系米制点云 | 仿真器的**米制场景点云** |
| Pose Head | 相机/底盘位姿、相对目标 | **真值相机外参 / 位姿** |

### 5) hᵖ 产出后去哪
- 拼给 World Point Fusion:`hʷ = A([hᵖ, hᶜ])` 聚合成世界系米制几何记忆;
- 喂规划器几何 query:`QG = CrossAttn(Qg, hᵖ/hʷ)`。

**一句话**:这里的真值点云是拿**仿真真值深度 + 内参**反投影算出的"标准答案",监督对象是 **Local Point Head 自己解码出的预测点云**,两者逐点回归;深度作输入是"尺度提示"、作监督是"重建答案",目的是逼网络输出比原始深度更鲁棒的几何、并把结构压进特征 hᵖ,故不构成循环。

## Q6. 规划核心详解:Localization Grounded Navigation Policy

对应论文第 IV-C 节,把前面所有隐式特征"收口"成动作。名字 **Localization Grounded**(定位锚定)即点题:**规划不是凭空生成,而是锚定在网络自估的定位/几何特征上。** 三段式:

```
隐式特征 hᶜ / hᵖ,hʷ + 相对目标 ĝ
   │(用 query 去"问")
State Query / Geometric Query / Goal Encoder
   │(拼接 → Transformer Decoder)
规划上下文 QP
   │(作为条件)
Diffusion Policy Head —— K 步去噪 → 动作序列
```

### 1) 先解决"相机系 vs 底盘系"错位
- **感知**在相机视角,**控制/规划**在底盘系,两者差一个"相机装在底盘什么高度/俯仰"的外参;跨平台时差异大。
- 传统靠**精确标定外参**对齐——"fragile and fails to generalize"(又脆又不泛化)。
- LoGoPlanner:**解耦**相机位姿与底盘位姿为两个独立任务,靠隐式特征桥接、**不标定**(假设相机相对底盘无 yaw);从 hᶜ 直接预测底盘位姿 Tb=`(x,y,θ)` 与相对目标 ĝ;相机/底盘位姿只差**固定外参 Text**(高度+俯仰),训练时随机化高度/俯仰 → 跨本体无需标定。

### 2) 三路规划条件:query-based 设计
规划器不吞 pose 数值/点云,而用**可学习 query 去"问"隐式特征**(灵感来自 UniAD):
- **State Query**:`QS = CrossAttn(Qs, hᶜ)` → 隐式自状态/定位;
- **Geometric Query**:`QG = CrossAttn(Qg, hᵖ/hʷ)` → 隐式环境几何/障碍;
- **Goal Encoder**:把**相对目标 ĝ**(已投影的动态目标,非原始全局 g)编码成 goal embedding。

三者拼接送 Transformer Decoder → **规划上下文 QP**(扩散头的条件)。
- 用 query 而非传数值:"**avoids cascading errors**...ensuring the final optimization target remains the **trajectory planning error**"——避免误差级联,全链路服务于把路走好。
- "Localization Grounded" 的落地:State Query 把规划**锚定在自定位特征 hᶜ 上**,这是它敢在无外部定位下规划的底气。

### 3) "用 query 去提取"到底什么意思(注意力机制)
本质就是 **Transformer 注意力**——"带着问题去检索":

| 角色 | 作用 | 在这里是谁 |
|------|------|------|
| **Query(Q)** | "我想问什么" | State/Geometric Query(可学习向量) |
| **Key(K)** | 每份资料的"索引" | 由 hᶜ / hᵖ 投影 |
| **Value(V)** | 每份资料的"内容" | 由 hᶜ / hᵖ 投影 |

流程(以 `QS = CrossAttn(Qs, hᶜ)` 为例):
1. **算相关度**:query 与 hᶜ 每个位置的 key 做点积 → 相关分数;
2. **归一化**:softmax → 权重(和为 1);
3. **加权汇总**:按权重把各位置 value 求和 → 输出 QS。
即 `QS = softmax(Qs·Kᵀ/√d)·V`,把一大片特征**按问题选择性浓缩成紧凑表征**。

**可学习 query**:不是人手写的问题,而是**随机初始化、随训练学出来的参数向量**——任务(轨迹误差)会逼它学会"该问什么"(State Query 学成问"我在哪/朝哪/目标在哪",Geometric Query 学成问"哪里有障碍")。

对比直接传特征的好处:

| | 直接传全部特征 | 用 query 提取 |
|------|------|------|
| 信息 | 又大又杂 | **选择性**,只留任务相关 |
| 尺寸 | 随输入变化 | **固定**(query 数决定) |
| 容错 | 上游误差一并塞入 | 按需取用,避免级联 |
| 可学 | 无法针对筛选 | **端到端学会该问什么** |

### 4) Diffusion Policy Head——条件变动作
- 输出 **action chunks** `{aₜ=(Δx,Δy,Δθ)}`,t=1…T(每步平面位移+转角);
- 从**高斯噪声 aᴷ** 出发,以 QP 为条件**预测噪声**、**迭代 K 步去噪** → 干净动作;公式(11)可读成 `下一步 = α·(当前带噪动作 − γ·ε(QP,动作,k) + 采样噪声)`。
- 为什么用扩散:导航动作是**多模态**的(左绕/右绕都对),直接回归会把两解平均成撞墙轨迹;扩散能建模多解并迭代收敛到**可行、无碰撞**轨迹。

### 5) 为什么整套成立(小结)

| 设计 | 解决的问题 |
|------|------|
| 解耦相机/底盘位姿 + 固定外参 Text | 跨本体(不同高度/俯仰)**无需标定** |
| query 交互隐式特征、不传数值 | 避免**误差级联**;规划锚定自定位 |
| 相对目标 ĝ 动态编码 | 移动中**目标不跟丢** |
| 扩散策略头 | 建模**多模态**、迭代出**无碰撞**轨迹 |

**一句话**:规划核心先用**解耦位姿+固定外参**摆脱跨平台标定,再用**三路 query(状态/几何/目标)**从隐式特征里"问"出规划条件、拼成 QP——全程**传特征不传数值**以避免误差级联、把规划**锚定在自定位上**(即 Localization Grounded);最后交**扩散策略头**以 QP 为条件、K 步去噪生成多模态、无碰撞的动作序列。
