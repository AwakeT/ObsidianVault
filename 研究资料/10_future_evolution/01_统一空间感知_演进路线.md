## 1. 北极星目标

> **用尽量统一的模型，对家居场景同时输出：语义感知 + 自身定位 + 可用地图。**

> ⚠️ **backbone 是可替换组件，不是目标的一部分。** DINOv2 只是**当前验证选型**（强几何/语义先验、生态成熟、与 VGGT 等前沿同构）；若出现更优/更易落地的视觉基座（其他自监督基座、几何基座本身、未来 foundation model），**直接替换**。真正承诺的是"**统一前向范式 + 多头/接口设计 + 数据与评测**"——这些与 backbone 解耦，换基座时各 head、Canonical Transform、数据 pipeline、ASM 接口尽量不变。

拆三块：

| 能力 | 含义 | 现状 |
|---|---|---|
| **感知（语义）** | 深度 / 检测 / 分割 / 房间 | ✅ DINO-GeoSemMap（10 号目录） |
| **定位** | 相机位姿 / 里程 | ⏳ 现用外部 SLAM；可演进为模型自出 |
| **地图** | 稠密点图 / 语义地图 / 场景图 | ⏳ 现用下游 ASM；可演进为模型持久状态 |

## 2. 前沿态势（2025–2026）

整个赛道在**收敛到"前向式统一 Transformer"范式**（这才是关键不变量；backbone 当前多用 DINOv2，但属选型、可替换），分三层推进：

### 第一层：几何基座（一次前向出 感知+定位+地图）

- **VGGT**（CVPR 2025 最佳论文）：N 图 → 相机位姿 + 每帧深度 + 3D 点图，一次前向、统一坐标系。**架构 = DINOv2 + camera token + 帧内/全局交替注意力 + DPT 稠密头**（≈ 我们的栈 + LingBot-Map）；
- **CUT3R**（CVPR 2025）：带**持久状态**的连续 3D 感知，流式在线维护隐式地图——最贴机器人；
- **MASt3R-SLAM / SLAM3R**（CVPR 2025）：上述先验做成实时稠密 SLAM；
- **MASt3R-Fusion**（2025）：融 IMU/GNSS，8GB 显存全局一致建图。
- 👉 **LingBot-Map（我们的 GCT）就在这一层。**

### 第二层：几何 + 语义**原生统一**（最贴我们目标）

- **UNITE**（2025/12）：指出 VGGT 类**只做几何不做语义**的空缺，提出在**一个网络里原生联合学几何 + 语义**，去掉"2D→3D 手工 lifting"；
- **Uni3R / UniSem**（2026）：在 VGGT（DINOv2）基座上加语义头，输出**带语义特征的 3D 高斯/点**。
- 👉 这层 = "我们的语义头 + VGGT 的几何/位姿头，挂同一个 DINOv2"，是我们演进的**直接参照系**。

### 第三层：语义地图 / 导航（地图模块 + 落地）

- **HOV-SG**：分层开放词汇 3D 场景图，**floor / room / object 三级**（含 room 层，对应我们房间头）；
- **DualMap**（2026）：在线、应对动态变化的开放词汇语义地图；
- **OpenMap / osmAG-LLM**：指令落地、物体被移动/未建图的鲁棒处理。
- 👉 这层**仍以模块化为主**（基座管语义、SLAM 管定位、地图做融合）。

> **房间分区属于这一层（地图模块），不是房间头的职责。** 房间头只出帧级房间**类型**（替代在线 VLM）；**分区**（房间实例 + 边界）由地图模块做——近期方案 A：**门检测（检测头）+ 自由空间（深度）+ 帧级类型投票** → 几何分区（分水岭/图割,门处断开）→ 房间实例 + 边界 + 类型（对标 HOV-SG 的 room 层）。中后期可演进为学习式 BEV 房间分割（方案 B）。详见 [09/§6 房间头 Scope](../09_dino_geosemmap_architecture/08_DINO-GeoSemMap_训练计划.md) 与 [09/11 输入输出与 ASM 对比](../09_dino_geosemmap_architecture/11_DINO-GeoSemMap_输入输出与ASM对比.md)。

### 现状判断

**尚无单一端到端模型同时做 几何+位姿+语义+地图+导航**；但"几何+语义原生统一"（第二层）正在 2026 发生，且全部以 DINOv2 为底——我们的技术押注与前沿一致。

## 3. 我们的演进路线

```text
P0 现状：DINO-GeoSemMap（冻结 DINOv2 + 单帧多头：深度/检测/分割/房间）
          位姿=外部 SLAM，地图=下游 ASM
   │
P1 几何/位姿基座：把 LingBot-Map（GCT，多帧几何+位姿）作为并行分支
          —— 模型开始自出位姿/点图（对标 VGGT/CUT3R）
   │
P2 几何+语义原生统一：在 DINOv2 上融合"语义头 + 几何/位姿头"
          —— 对标 UNITE/Uni3R/UniSem，去掉手工 2D→3D lifting
   │
P3 语义地图/持久状态：模型维护可导航语义地图
          —— 房间分区(门+自由空间+类型投票) / CUT3R 持久状态 / HOV-SG 场景图 / 升级版 ASM
```

| 阶段 | 目标 | 复用资产 | 对标 |
|---|---|---|---|
| **P0** | 家居语义感知可用 | DINO-GeoSemMap | — |
| **P1** | 模型自出定位/点图 | LingBot-Map (GCT) | VGGT / CUT3R |
| **P2** | 几何+语义同网原生统一 | P0 头 + P1 几何分支 | UNITE / Uni3R |
| **P3** | 可导航语义地图 | ASM + 房间/物体语义 | HOV-SG / CUT3R |

## 4. 关键架构岔路（早想清楚）

**1、单帧冻结 vs 多帧位姿**
当前深度头是**冻结 backbone + 单帧**。但定位/位姿（VGGT/CUT3R/LingBot-Map）**本质需要多帧跨视注意力**（LingBot 的 GCA），通常还要**解冻/多帧适配 backbone**。
→ "加定位"≠ 再加一个冻结单帧头，而是一个**多帧几何分支**，是独立子架构。

**2、位姿：外置 SLAM vs 吸进模型**

|          | 外置 SLAM（P0 现状） | 吸进模型（VGGT/LingBot 式） |
| -------- | -------------- | -------------------- |
| 落地速度     | 快、当下最稳         | 慢、需训练                |
| 统一度      | 模块化            | 高                    |
| backbone | 可全冻结           | 多半要动                 |

→ 建议：**短期感知冻结多头 + 定位交 SLAM；中期再把多帧几何/位姿分支与语义头在同一 backbone 上融合**（走 P2）。

**3、地图形态**：稠密点图 / 占据 vs 语义高斯 vs 场景图(floor/room/object) vs ASM —— 按导航/VLN 下游需求定。

**4、backbone 选型**：DINOv2 = 当前验证选型，非绑定（见 §1）。换基座时尽量保持各 head / Canonical Transform / 数据 pipeline / ASM 接口不变，把 backbone 做成可插拔。评估新基座的标准：几何+语义先验质量、可冻结/可缓存性、端侧可部署性、与几何/位姿分支的兼容度。

## 5. 与现有资产的关系

- **DINO-GeoSemMap**（10 号目录）= P0 的语义感知层，是 P2 的"语义头"来源；
- **LingBot-Map / GCT** = P1 的几何/位姿基座，是 P2 的"几何头"来源；
- 两者**共享同一 backbone（当前 DINOv2）+ DPT 头 + 多尺度 [4,11,17,23] 特征**的同构性，正是能在 P2 融合的前提；换 backbone 时这套同构关系应一并平移。
