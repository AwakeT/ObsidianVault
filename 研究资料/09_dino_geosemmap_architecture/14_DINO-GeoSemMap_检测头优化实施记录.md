## 0. 摘要

检测头从首轮的"完全不可用"推进到"可用、稳定、能泛化"，但**可部署口径下仍未达标**。

- **瓶颈翻案**：检测头首轮卡死的原因不是冻结特征不行，而是 **DETR 头**不行（数据饥饿 + 匈牙利匹配不稳 + 过训坍塌）。换成 **FCOS 密集头**后，同一冻结特征 train recall 从 20%（且坍塌）升到 97%（稳定）。FCOS 定为生产头。
- **扩数据有效**：COCO train2017 35326 穷尽图训练，val2017 held-out 上 train≈val，确认是真泛化而非记忆。
- **置信度**：focal 系统性压低分数 → 换 **Quality Focal Loss + Platt 标定**，可部署 `recall@conf0.5` 从 ≈0 提到 26%。
- **当前瓶颈 = 精度（假阳多）**：FP 主要是定位差 + 背景幻觉。已上 **DFL** 攻定位；**D2a（检测私有可训练 adapter）已完成**——标定 `recall@conf0.5` 26%→**31.8%**、容量 81%→89%、定位 FP 47%→40%，**证实冻结后端确在拖精度（部分成立，非唯一主因）**；但瓶颈转移到**背景幻觉 FP_bg（50%，第一大头）**，下一主攻。
- **口径**：`conf0.05` / `top300` 是诊断口径、部署不可用；一律以 **标定后 `recall@conf0.5`** 为验收。

**当前可部署成绩：`recall@conf0.5` ≈ 31.8%（D2a 后；冻结基线 26%；目标 70%）。**

## 1. 背景与目标

### 1.1 起点

首轮中小规模训练后，检测头是四个推理头中唯一卡在"不可用"的：

- DETR 风格头，val recall ~12.8%（LVIS L2，1.97 万图），conf p99≈0.3，`conf0.5` 处几乎无输出。
- 过训坍塌：det_v1 在 step5000 见顶后退化，到 step20000 已接近 0。

### 1.2 目标与验收口径

- **目标**：可部署 `recall@conf0.5` 逼近 08 文档 M2 验收线 **70%**。
- **口径约束**：`conf0.05`、`top300` 仅作诊断期能力上限参考；部署会保留数百框，不可用。**唯一验收指标 = 标定后的 `recall@conf0.5`。**

### 1.3 方法论原则

按 13 方案的"诊断优先"：每次"换头 / 换损失 / 扩数据"之前，先用受控实验把 **A（数据）/ B（特征）/ C（动力学）** 三个病灶解耦，再对症投入，避免盲目堆算力。

## 2. 诊断阶段：定位瓶颈

### 2.1 D0 · train vs val recall（零训练，DETR 头）

复用训练同一切分，直接评估已有 ckpt：

| ckpt | 数据 | train recall | val recall |
|---|---|---|---|
| det_v2 | LVIS L2（17.7k） | 15.0% | 12.8% |
| det_v1 | COCO L1（1.5k） | 19.9% | 19.3% |

**判读**：两组均 train≈val 且双低（<20%）。模型连训练集都拟合不上 → 不是泛化 / 数据量问题，指向 B（特征）或头 / 动力学。

脚本 `scripts/diag_det_d0.py`。自检锚点：det_v2 val=0.1284 与 ckpt 记录值精确对齐。

### 2.2 D1 · DETR 头在 1504 穷尽集故意过拟合

同分布 train≈val、多 epoch，观察冻结特征的拟合上限：

train recall 曲线：`9.8 → 14.8 → 18.8 → 19.9%（峰 @6k） → 坍塌 3.5%（@7k） → 1.1%（@8k）`。

**初判**：冻结特征天花板 ≈ 20%，倾向 B（特征上限）。

**遗留隐患**：这个 20% 是①用 DETR 头测的、②被坍塌截断的。两个混淆变量未排除，结论不可信——下一步验证。

### 2.3 D1' · 换 FCOS 头，同冻结 base + 同 1504 集（关键对照）

**唯一变量 = 检测头范式**（密集 anchor-free vs DETR 稀疏 query），其余全部固定：

train recall 曲线：`54 → 76 → 91 → 96 → 97.3%`，val top300 ~51–56%，**全程不坍塌**。

| 同冻结特征 + 同 1504 集 | train 峰值 | step6000 行为 |
|---|---|---|
| DETR 头 | ~20% | 坍塌 → 3.5% |
| FCOS 头 | **97%** | 稳定 |

### 2.4 诊断小结

- **推翻"容量层面 B"**：冻结 DINOv2 + 共享 Adapter 的特征足以支撑 97% train recall，能"找到"物体。D1 的 ~20% 是 DETR 头（稀疏 query + 匈牙利匹配 + 坍塌）造成的，不是特征上限。
- **坍塌是 DETR 专属病**：FCOS 在 DETR 的坍塌点（step6000）稳定，换头即免疫。
- **剩余开放问题**：train 97% vs val ~52% 的差距指向 A（数据 / 泛化）；而"高置信精度"层面的 B 尚未回答（见 §9）。

## 3. 框架选型：FCOS 定为生产头

### 3.1 部署硬件约束

- 板端目标硬件 = 地瓜 RDK **S100P**（地平线 Nash BPU，128 TOPS int8）。VPU 可跑 LayerNorm / Softmax，ViT 可部署（SigLIP 已验证）。
- 核心架构需求 = **DINOv2 冻结 backbone + 检测头与其他任务头无损合并**。该约束对检测框架几乎无限制——任何"纯吃冻结金字塔特征"的头都满足无损合并。

### 3.2 选型理由

框架选型回到精度 / 稳定 / 简洁三项：

| 候选 | 结论 |
|---|---|
| DETR | ✗ 已证伪（数据饥饿、坍塌） |
| YOLOv8 | ✗ 复杂度无必要（脚手架曾搭后清理） |
| **FCOS 密集 anchor-free** | ✓ 已验证、最简、合并友好 |

**决策：FCOS 定为生产检测头。**

## 4. 优化战线一：扩数据

针对 §2.4 指出的 A（数据 / 泛化）：

- **数据**：`prep_coco.py --split train2017` 生成 `det_cocotrain_L1.jsonl` = **35326 图 / 95548 实例**（穷尽标注，11 个家居 OBJ30 类：bed / chair / dining_table / microwave / oven_stove / potted_plant / refrigerator / sink / sofa / toilet / tv）。
- **训练**：COCO train2017 35326 → held-out val2017 1504（与 1504 过拟合实验同一 val，可直接比较）。
- **结果**：val top300 ~61%、`@.05` ~74%，**train≈val（真泛化，非记忆）** → 证实数据有效、容量充足。

工具：`train_fcos.py --train_manifests / --val_manifests`（干净 held-out）。

## 5. 优化战线二：置信度

核心障碍是"高置信高召回"——能力上限够，但分数集中在低区间，`conf0.5` 处几乎无输出。

### 5.1 诊断：conf 低的真凶

统计 val 上被正确召回的框（TP）的分数分布：

| TP 分数口径 | p50 | p90 | frac>0.5 |
|---|---|---|---|
| cls×ctr（旧） | 0.122 | 0.305 | 0.000 |
| cls-only | 0.163 | 0.387 | 0.018 |
| centerness | 0.765 | 0.827 | 0.999 |

**判读**：真凶是 **cls 头 focal 系统性压低分数**（centerness 反而高，不是元凶）；去掉 cls×ctr 双乘也救不了。

### 5.2 QFL（Quality Focal Loss）

把 cls 目标从硬标签 {0,1} 改成**预测框与 GT 的 IoU 软标签**，分数被训去贴合框质量；去掉独立 centerness（质量信息并入 cls 分数）。

- **效果**：TP 分数 p50 0.12 → 0.245，frac>0.5 0 → 15%；raw `recall@conf0.5` 13%。

### 5.3 Platt 置信度标定

QFL 分数仍系统性偏低。纯温度缩放救不了"欠置信"，改用 **Platt（温度 + 偏置）**：

```
标定分 = sigmoid(a · logit(分数) + b)      （于 val 上拟合 a=2.789, b=1.350）
```

使"标定分 0.5"≈"50% 可能正确"。

| conf | raw recall | 标定后 recall |
|---|---|---|
| 0.4 | 23.9% | 30.3% |
| **0.5** | **13.1%** | **26.0%** |
| 0.6 | 4.7% | 22.1% |

**可部署 `recall@conf0.5`：13% → 26%。**

> 标定是单调变换，只重贴刻度、不增加区分度。它把可用门槛抬出来的同时，也**暴露了真正的瓶颈是精度**（见 §6）。

## 6. 优化战线三：精度（当前瓶颈）

标定后召回上不去，根因是假阳太多——精度是当前主瓶颈。

### 6.1 FP 成分诊断（thr0.2 + NMS0.5，可部署口径）

precision 0.292 / recall 0.487，假阳构成：

| FP 类型 | 占比 | 含义 |
|---|---|---|
| **FP_loc** | **47.2%** | 类别对、IoU 0.1–0.5（定位差，差一点过 0.5） |
| **FP_bg** | **38.9%** | 背景幻觉（离 GT 远，凭空报框） |
| FP_dup | 8.7% | NMS 漏掉的重复框 |
| FP_cls | 5.2% | 位置对、类别错 |

脚本 `scripts/diag_det_fp.py`。**主攻方向 = 定位（47%）+ 背景（39%）两块。**

### 6.2 DFL 框回归（攻 FP_loc）

把 box 从单点回归改成**分布式回归**（每条边 reg_max=16 个 bin）：

- 机制：框收紧 → 精度↑，且"差一点的框"跨过 0.5 IoU → 召回↑。
- 结果（**未训熟即停 @step15k**）：`@.05` 容量升到 81%（本轮最高），raw `conf0.5` 升到 10%。
- **状态：未收敛，待训熟 + 标定后才能给出对 FP_loc 的真实增益。**

### 6.3 背景抑制（攻 FP_bg）—— 待落地

FP_bg 占 39%，与 FP_loc 几乎等量，但 DFL 和 adapter 都不直接攻它。**当前无专门手段，是最大盲点。**

> **注意**：用 QFL 时为把质量并入 cls，去掉了独立 centerness，等于撤掉了"前景 / 背景"这道置信门控——这可能是 FP_bg 偏高的直接原因之一。具体落地与归因诊断见 §8.3。

### 6.4 松动阶梯（D2a / D2b）

在不破坏无损合并的前提下，逐档松动特征，验证"冻结后端是否限制高置信精度"：

| 档 | 松动方式 | 可训练参数 | 满足无损合并 | 状态 |
|---|---|---|---|---|
| L0 | 冻结 adapter（现状基线） | 0 | ✓ | 基线 26% |
| **L1 = D2a** | 私有可训练 adapter（深度 adapter 暖启动） | 9.3M | ✓ 检测专属分支 | **完成（step28k）** |
| **L2 = D2b** | + LoRA backbone 末层 | 少量 | ✓ 检测专属 LoRA | 未开始 |
| L3 | 解冻 backbone 末 N 层 | 较多 | ✓ 但分支变重 | 备选 |

- **D2a 做法**：`train_fcos.py --train_adapter`，adapter 从深度 adapter 暖启动后可训练，与 FCOS 头联训，DINOv2 backbone 仍冻结。可训练参数 9.3M。
- **D2a 结果（step28000，标定后 vs 冻结基线）**：

| 指标 | 冻结基线 | **D2a** | 变化 |
|---|---|---|---|
| **标定 `recall@conf0.5`** | 26.0% | **31.8%** | **+5.8** ✓ |
| raw `recall@conf0.5` | 13% | 20% | +7 |
| `@.05` 容量 | 81% | **89%** | +8 |
| FP-diag recall（thr0.2） | 0.487 | **0.621** | +13 |

  FP 成分变化：**FP_loc 47.2% → 39.8%（↓，DFL+adapter 收紧框）**，但 **FP_bg 38.9% → 50.3%（↑，反成第一大头）**；FP_dup 8.7%→6.0%、FP_cls 5.2%→3.9%。Platt 重拟合 a=2.908, b=1.014。

- **判读**：训私有 adapter **确有效**——标定 `recall@conf0.5` +5.8 点、容量 +8、定位 FP 下降。**证实冻结后端确实在拖精度（§9 精度层面 B 部分成立）**。但 ① 增益温和（离 70% 仍远）；② **瓶颈转移到背景幻觉 FP_bg（50%）**——部分是 QFL 去 centerness 撤掉前景门控的"自伤"（见 §6.3/§8.3），adapter 让特征更活也更易在背景误报。**下一主攻 = FP_bg。**

## 8. 后续计划

### 8.1 推进策略：消融式

逐条战线隔离加入 + 重新标定，每条都量出独立增益。既推进效果，又产出"哪个手段贡献多少"的归因数据。

### 8.2 Step 1 · 先收口已在训的两项

- **D2a 训熟 + 标定（✓ 已完成）**：step28k，标定 `recall@conf0.5` 26→31.8%、FP_loc 47→40%、FP_bg 39→50%。结论见 §6.4 / §9——松动有真实增益，瓶颈转向 FP_bg。
- **DFL 单独训熟（可选）**：当前 DFL 已并入 D2a 一起训；若要单独量 DFL 对 FP_loc 的净增益，可在冻结 adapter 下补一轮。优先级低于 §8.3 背景抑制。

### 8.3 Step 2 · 背景抑制（攻 FP_bg）

在 Step 1 的最佳基线上进行。**动手前先做归因诊断，避免攻错层面：**

> 统计背景幻觉框的 **cls logit 分布**：
> - 背景框 cls 分数**本就偏高、与前景重叠** → FP_bg 根因是**特征分不开前景 / 背景**，属精度层面 B，需靠 §6.4 的松动（L2/L3），单纯调采样压不下；
> - 背景框分数**本该低却被放大** → 是损失 / 采样问题，下列手段可直接解。

落地手段（诊断指向损失 / 采样时）：

1. **加回独立 objectness / 前景分支**：最终分 = cls × objectness，背景位置 objectness 被压低 → 抑制 FP_bg。对应 §6.3 指出的"撤掉前景门控"问题。
2. **hard negative mining / 难负样本加权**：重点惩罚"最像物体的背景"。
3. **center sampling 收紧正样本定义**：让前景 / 背景监督边界更干净。

### 8.4 Step 3 · 按需松动（D2b）

若 Step 1 的 D2a + Step 2 的背景抑制叠加后仍够不到目标，或 §8.3 诊断指向"特征分不开"，再上 D2b（LoRA 松动 backbone 末层）。

### 8.5 贯穿全程的纪律

- **每改一次模型，Platt 标定重做一遍**（标定在特定模型的 val 分数上拟合，换模型刻度即变），`recall@conf0.5` 必须取标定后数值。
- **`conf0.05` / `top300` 只看不认**，一切验收以标定后 `conf0.5` 为准。

## 9. 冻结后端假设的演进

这是贯穿全程的一条认知主线，记录"冻结特征到底是不是瓶颈"的判断如何随证据更新：

| 阶段 | 判断 | 证据 |
|---|---|---|
| D1（§2.2） | 冻结特征是**容量**瓶颈（天花板 ~20%） | DETR 头过拟合上限 20% |
| D1'（§2.3） | **推翻容量层面 B** | 换 FCOS，同特征 train recall 97% |
| 精度战线（§6） | **精度层面 B 重新打开** | FP_loc + FP_bg 高 |
| **D2a（§6.4）** | **精度层面 B 部分成立** | 训私有 adapter，标定 `recall@conf0.5` 26→31.8%、容量 81→89%、FP_loc 47→40% |

- **已证明**：冻结特征不是**召回容量**的瓶颈（D1' train 97%）。
- **部分证明**：冻结特征**确在拖高置信精度**——松动（私有 adapter）有 +5.8 点的真实增益。**但它是温和增益、非银弹**：D2a 后剩余的最大缺口转为**背景幻觉 FP_bg（50%）**，而后者部分是"去 centerness 撤了前景门控"的损失设计自伤，不是纯特征问题。
- **修正判断**：冻结后端是**贡献因素之一**而非唯一主因。后续应"松动（D2a 已拿/D2b 备选）+ 背景抑制（§8.3）+ 扩数据"叠加推进，而非指望单一手段。

## 11. 方法论收获

1. **诊断优先反复奏效**：D1'（换头对照）一次推翻误判的 B；conf 诊断（TP 分数分布）一次定位 focal 是 conf 低的真凶；FP 成分诊断一次指明定位 + 背景是主攻方向。每次投入前先解耦变量。
2. **口径决定结论**：`conf0.05` 的 81% 看似漂亮但部署无用；钉死可部署的 `conf0.5` 后，真实成绩（26%）和真瓶颈（精度）才浮现。
3. **混淆变量要警惕**：D1 的 ~20% 把"DETR 头无能"误读成"特征上限"，靠 D1' 排除头的混淆才翻案。结论必须在排除混淆后才可信。
4. **标定不是免费午餐**：单调变换只重贴刻度、不造区分度，但能让高置信门槛可用、并暴露真瓶颈。
