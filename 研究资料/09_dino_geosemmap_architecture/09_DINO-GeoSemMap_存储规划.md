## 0. 文档定位

本文从 [08 训练计划](08_DINO-GeoSemMap_训练计划.md) 抽出并细化**各阶段/各轮次的存储需求**，覆盖：数据集存储、特征缓存、模型/checkpoint 产物、本地↔云的存储分布，以及总量规划建议。

口径与 08 一致：
- 数据量分 **最低（起步）** 与 **完整（较好效果）** 两档；
- 推进分 **预验证轮 → 正式首轮 → 完整数据轮**（[08 §2.1](08_DINO-GeoSemMap_训练计划.md)）；
- 硬件 **深度本地 PRO6000 + 检测/分割/房间上云**（[08 §8.1](08_DINO-GeoSemMap_训练计划.md)）。

---

## 1. 数据集存储（按模块 / 阶段）

每样本经验大小（RGB 压缩图 + 标注；深度数据含 16-bit 深度图 + valid mask）：

| 模块 | 每样本约 | 最低数据量 | 存储 | 完整数据量（较好效果） | 存储 |
|---|---|---|---|---|---|
| Depth（阶段0） | ~0.5 MB | 50 万帧 | ~250 GB | 200–500 万帧 | **~1.0–2.5 TB** |
| Detection（阶段1） | ~0.2 MB | 10 万张 | ~20 GB | 50–100 万张 | ~100–200 GB |
| Mask（阶段2） | ~0.3 MB | 5 万张 | ~15 GB | 30–100 万张 | ~90–300 GB |
| Room（阶段3） | ~0.15 MB | 5 万帧 | ~7.5 GB | 20–80 万帧 | ~30–120 GB |
| **合计** | | | **~0.3 TB** | | **~1.2–3.1 TB** |

- **深度数据是绝对大头**（帧数最多 + 深度图本身大），占完整数据轮的 80%+；
- 每样本大小随原始分辨率/编码浮动（约 0.3–1 MB/帧），上表取中值；
- 完整数据轮总量随"较好效果"落点在 **1.2–3.1 TB** 间浮动（[08 §2.1](08_DINO-GeoSemMap_训练计划.md) 取 ~1.5 TB 对应较好效果下限）。

## 2. 数据集存储（按推进轮次）

> 口径：每一轮都对**全部四个 head（深度/检测/分割/房间）**做效果确认（[08 §2.1 铁律](08_DINO-GeoSemMap_训练计划.md)），故各轮存储**含四个 head 的数据**，不再把 Mask/Room 推迟到最后。

| 轮次 | 内容（四 head 全覆盖） | 存储（约） |
| --- | --- | --- |
| **预验证轮** | L0 smoke 数千样本 + L1 小量(深度1–5万/检测1–2万/分割·房间各1–2万) + L2 中量(深度10–20万/检测·分割·房间各3–5万) | **~0.02–0.1 TB** |
| **正式首轮** | 原型：深度 50–100万 + 检测 10–30万 + 分割 5–20万 + 房间 5–20万 | **~0.3–0.65 TB** |
| **完整数据轮** | 四 head 较好效果 | **~1.2–3.1 TB** |

> 各轮数据可累积复用（预验证 ⊂ 首轮 ⊂ 完整），不必重复存储；上表为各轮**全量**口径。
> Mask/Room 数据体量小（每样本 0.3 / 0.15 MB），加进首轮后存储上限从 ~0.55 → ~0.65 TB，增量有限。

## 3. 特征缓存存储（可选，用存储换算力）

阶段1/2/3 的 backbone+Adapter 全冻结，可预缓存 Adapter 输出 P2–P5 复用多 epoch（[08 §8.3](08_DINO-GeoSemMap_训练计划.md)）。但特征体积大：

```text
P2–P5（FP16, @518）≈ 15 MB/图
（P2 130²×256 + P3 65²×512 + P4 33²×1024 + P5 17²×1024 ≈ 7.9M floats × 2B）
```

| 缓存对象 | 最低数据量 | 完整数据量 |
|---|---|---|
| Detection 特征 | 10 万 → ~1.5 TB | 100 万 → **~15 TB** |
| Mask 特征 | 5 万 → ~0.75 TB | 100 万 → ~15 TB |
| Room 特征 | 5 万 → ~0.75 TB | 80 万 → ~12 TB |

> ⚠️ **完整数据量下特征缓存体积是原始数据集的数十倍，通常不划算**。
> 建议：完整数据轮在云端**直接 re-forward**（DINOv2+Adapter 算力便宜）；仅在小/中量、多 epoch 反复复用、且存储充裕时才缓存。

## 4. 模型 / Checkpoint 产物存储

均为 **GB 级，相对数据集可忽略**，但需为版本管理预留：

| 产物 | 大小（约） | 说明 |
|---|---|---|
| DINOv2 ViT-B 冻结权重 | ~0.17 GB | 公开权重，可引用不另存 |
| 训练 checkpoint（含 AdamW 优化器状态） | ~0.3–0.5 GB / 份 | 仅可训练 ~20–35M 参数；保留 last N + best ≈ ~1–2 GB |
| **冻结特征基座导出**（DINOv2+Adapter，推理权重） | **~0.2–0.3 GB** | 交云端训各 head 用；需 hash 钉死版本（[08 §8.1](08_DINO-GeoSemMap_训练计划.md)） |
| 各 head 推理权重 | 合计 ~60 MB | heads ~30M × 2B |
| **最终装配单模型**（v0.3-B FP16） | **~230 MB** | 见 [07 §12.2](07_DINO-GeoSemMap_架构设计.md)；INT8 量化 ~115 MB |
| 日志 / TensorBoard | ~GB 级 | |

## 5. 本地 ↔ 云 存储分布

按 [08 §8.1](08_DINO-GeoSemMap_训练计划.md) 的硬件分工，存储也随之分布——**大头在本地（深度），云端数据反而小**：

| 位置             | 存放                       | 最低      | 完整              |
| -------------- | ------------------------ | ------- | --------------- |
| **本地 PRO6000** | 深度数据集 + 冻结基座导出 + 深度 ckpt | ~0.3 TB | **~1.0–2.5 TB** |
| **云平台**        | 检测/分割/房间数据集 + 上传的冻结基座    | ~40 GB  | ~0.2–0.6 TB     |

> 反直觉但重要：**本地机器才是存储压力大头**（深度数据），云端只需放体量小得多的检测/分割/房间数据集。

## 6. 总量规划与建议

| 场景 | 本地需求 | 云需求 |
|---|---|---|
| 预验证轮 | <0.1 TB（任意盘即可，全程本地） | — |
| 正式首轮 | ~0.25–0.5 TB（仅深度） | ~40–150 GB（检测+分割+房间） |
| 完整数据轮 | ~1.0–2.5 TB（仅深度） | ~0.2–0.6 TB（检测+分割+房间） |

**建议配置：**

- **本地**：~**4 TB NVMe**（容纳完整深度数据 + 留余量；NVMe 保障多分辨率 dataloader 吞吐，避免成为训练瓶颈）；
- **云**：~**1 TB 对象存储/块存储**（检测/分割/房间数据集 + 基座）；
- **预留 10–20%** 给增强中间产物、临时 cache、日志、多版本 ckpt；
- **完整数据轮避免特征缓存**（见 §3），用 re-forward 替代，省下数 TB～十几 TB。
