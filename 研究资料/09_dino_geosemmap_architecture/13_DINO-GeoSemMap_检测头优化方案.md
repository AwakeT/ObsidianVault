## 0. 文档定位

本文是首轮中小规模数据集训练后，针对 **检测头（Stage1）** 的专项优化方案。

**本轮范围（重要）**：经讨论确定，**本轮只打检测头一个头**。深度（已达标）、分割（下游鲁棒、暂够用）、房间（待优化）三头本轮不动，相关思路存为 §7 下一轮备忘。集中火力把唯一卡在"不可用"的检测头打透。

**核心打法**：**诊断优先**——先用小数据/低算力把瓶颈解耦定位，再对症投入，不盲目砸算力。

## 1. 检测头现状（首轮中小规模实测）

来自实验记录的检测头实验序列：

| 实验 | 数据 | 类数 | 图/实例 | best recall | 备注 |
|---|---|---|---|---|---|
| Run1 cocotrain | COCO train2017 | 11 | 35326 / 95548 | ~26%@conf0 / 22%@0.05 | step5000 见顶后坍塌到 6% |
| Run2 LVIS+balance | LVIS L2 | 25 | 19696 / 64239 | 12.8%@conf0.05 | 覆盖广、不再单类坍缩 |
| 消融 trainable-adapter | LVIS L2 | 25 | 同上 | 12.2%@conf0.05 | 关键结论：解冻 Adapter 几乎无改善 |

**已发现并修复/记录的问题：**

- **eval 阈值假象**：`score_thr=0.3` 把 DETR 低置信正确框全滤掉 → 日志 recall≈0 假象。已修：训练/评估改 conf 0.05 口径（目标口径后续为 0.5）。
- **过训坍塌**：step5000 后 set loss 仍降但检测退化（recall 26%→6%，置信度走低）。当前缓解：短 schedule + best.pt 抓峰值。
- **置信度极低**：p99≈0.3，conf≥0.5 处几乎无输出 → 这是达成"高置信高召回"目标的**核心障碍**。

**三个待解释的关键事实：**

1. 当前 12.8% 是在 **LVIS L2 仅 ~1.97 万图**上测的，而 08 文档检测起步线是 **10–30 万图**——差一个数量级。这是后续一切对照实验的**混淆变量**。
2. `trainable-adapter` 解冻 Adapter 后 recall 12.8→12.2（反而略降）。**但这可能是小数据上 LoRA/解冻参数更多、更易过拟合的假象，不能直接判定"松动无用"。**
3. `conf p99≈0.3` 的系统性低置信，与 LVIS 的**非穷尽标注**高度相关（见 §2）。

## 2. 诊断框架：三个可区分的瓶颈假设

检测头的"病"拆成三个指向**完全不同药方**的病灶，本轮目标是先把它们**解耦**：

| 假设 | 含义 | 若成立的解法 | 扩数据是否有用 |
|---|---|---|---|
| **A 数据量 / 质量** | 2 万图 vs 起步 10–30 万差一个量级；LVIS 长尾 + 非穷尽标注 | 扩穷尽标注数据、federated loss | ✅ 有用 |
| **B 冻结特征实例判别力** | DINOv2 自监督特征偏全局语义；且共享 Adapter 被深度任务**几何锚定**，对实例定位不友好 | 私有 adapter / LoRA 末层 | ❌ 无用（特征是硬上限） |
| **C 训练动力学 / decoder** | 过训坍塌、conf p99≈0.3：匈牙利匹配震荡 / loss 权重 / focal / query 配置 | DN-query、EMA、loss 重配 | ❌ 无关（确定性病灶） |

> **共同根源猜想**：共享 Adapter 是阶段0 跟着 metric depth（纯几何任务）训出来后冻结的，其特征基座**可能对语义/实例任务不友好**（08 文档 §11 风险表第二条）。这同时是 B 假设的可能根源。诊断阶梯 D2 正是验证它的关键。

> **非穷尽标注 → 低置信链条（最可疑、可能"免费"的突破口）**：LVIS 图里有物体却未标注，DETR 把这些正确预测当假阳性惩罚 → 模型学会"**不敢报**" → 直接压低置信度。这很可能正是 `conf p99≈0.3` 的真凶，而非特征或能力问题。D3 专门验证。

## 3. 第一步：诊断阶梯（解耦归因，小数据 / 低算力）

每一阶几乎不花算力（都在现有小数据上），却能逐步排除一个假设。

### D0 · 训练集 recall 基线（零成本）

- **动作**：从现有 Run1/Run2 日志取（或重跑评估）**train recall vs val recall**。val recall 12.8% 孤立看没有意义，必须对照训练集。
- **判读**：
  - train 也低（如 <30%）→ **欠拟合 / 特征上限（B）**，排除"数据量不够"——现有数据都没学会，加数据无意义；
  - train 高、val 低 → **泛化 / 数据量（A）**，特征够用。
- **产出**：A 与 B 的初步劈分。

### D1 · 穷尽标注小集"故意过拟合"（A/B 分水岭）

- **数据**：COCO val 那 **1504 图穷尽标注 11 类**，同分布 train≈val、多跑 epoch、**故意过拟合**。
- **判读**：冻结特征下 train recall 的**上限** = DINOv2 冻结特征 + 当前 Adapter 的实例判别力**实证天花板**。
  - 冲不上去（卡在 40–50%）→ **B 实锤**，扩数据无用；
  - 能冲很高（>90%）→ 特征够用，瓶颈在 **A**。

### D2 · 同集 冻结 vs 松动（回答铁律 + 验证共同根源）

- **动作**：在 D1 **同一小集**上分别叠加 ①LoRA(backbone 末层) ②检测私有 adapter，对比 train recall 上限。
- **判读**：
  - 松动**抬高**了 D1 上限 → 特征/Adapter 锚定确是瓶颈，**松动有价值**，回答了"冻结铁律本轮是否该松"；
  - 松动**没抬高** → 冻结特征不是瓶颈，前期 `trainable-adapter 12.8→12.2` 不是过拟合假象、而是真信号，应把火力转向 A/C。
- **意义**：用小数据上的受控对照，干净回答了"DINOv2 全程冻结"这条铁律本轮是否松动——避免在 2 万图大混淆变量上误判。

### D3 · 标注密度对照（隔离 conf 低的真凶）

- **动作**：穷尽标注（COCO 全量映射）vs 非穷尽（LVIS）**同规模**训练，对比 **conf 分布（p99 等）**。
- **判读**：换穷尽标注后 conf 显著回升 → "低置信"主因是 **LVIS 稀疏标注惩罚**，解法是 **federated loss（对未标注区域不惩罚）+ 穷尽标注数据**，几乎不动结构即可大幅缓解核心障碍。

**诊断阶梯产出**：A / B / C 的明确主因归属（可能多因并存，但能定主次）。

### 3.5 诊断实测结果（2026-06-08，D0 + D1 已跑）

**D0 · train recall vs val recall（零训练，复用训练同一切分 seed0/val_frac0.1）**

| ckpt | 数据 | train recall | val recall | gap | score p99 |
|---|---|---|---|---|---|
| det_v2/best (step6500) | LVIS L2（17.7k 训练图） | 15.0% | 12.8% | +0.02 | 0.32/0.33 |
| det_v1/best (step5000) | COCO L1（1.35k 训练图） | 19.9% | 19.3% | +0.01 | 0.34/0.32 |

> 两组**均 train ≈ val、双低（<20%）、gap≈0**：模型连训练集都拟合不上，**不是泛化/数据量问题**。
> 按 D0 判读 → 直接指向 **B（欠拟合 / 冻结特征上限）**，初步排除 A。脚本 `scripts/diag_det_d0.py`；
> 自检锚点：det_v2 val=0.1284 与 ckpt 记录值精确对齐。

**D1 · 1504 穷尽集"故意过拟合"（冻结 base，bs8，40k 计划，`--eval_train`）**

train recall 曲线（step→train_recall）：
`1k:9.8% → 2k:9.8% → 3k:11.4% → 4k:14.8% → 5k:18.8% → **6k:19.9%(峰)** → 7k:3.5% → 8k:1.1%`

> - **冻结特征天花板 ≈ 20%**（step6000 峰值）。即便高容量头（6层decoder+300query）在 **1354 图**上故意过拟合，
>   train recall 也**冲不到计划设的 B 阈值 40–50%，更远不及 90%** → **B 实锤**：冻结 DINOv2 + 深度锚定共享 Adapter
>   的特征**撑不起实例判别**，**扩数据（A）救不了当前天花板**。
> - 全程 **train≈val、几乎不张开过拟合 gap**（1354 图上头都不"记忆"）——进一步坐实 B。
> - **C 实锤（过训坍塌）**：step6000→7000 干净坍塌（20%→3.5%，持续恶化不恢复），与 det_v1 一致、与数据集无关，
>   是**确定性训练动力学病灶**。ckpt `checkpoints/det_d1_overfit/best.pt` 抓住峰值 step6000。

**结论（本轮软产出，与硬指标同等重要）**：

- **主因 = B（冻结特征/Adapter 锚定）**，**A 基本排除**（廉价证伪，避免盲目扩大数据轮）；**C 并存**（坍塌）。
- **重要 caveat**：D1 的 ~20% 是被坍塌（C）**截断**的天花板，是**下界**而非干净上限。要拿到精确天花板并干净跑 D2，
  需**先稳住 C**（EMA / 降 LR / short schedule + best.pt）让过拟合不在 step6000 被打断。
- **下一步（按 §4）**：① **D2** 验证私有 adapter / LoRA 末层能否抬高这 ~20% 天花板——若能抬高，深度锚定 Adapter
  即元凶，检测私有 adapter 是正解（最高价值实验）；② **C 稳定化**与 D2 并行，先把坍塌摁住再读 D2 的干净上限。

### 3.6 诊断翻案（2026-06-08，D1' 换头实验）— **B 被推翻，真凶是 DETR 头**

**质疑 D1 的隐藏混淆**：D1 的 ~20% 是**用 DETR 头**测的，那个天花板其实是「冻结特征 **+ DETR头 + 坍塌**」三者纠缠。
DETR 恰是冻结特征/小数据下最差的头（稀疏 query、匈牙利匹配震荡、过训坍塌）。于是做 **D1'**：
**唯一变量 = 检测头范式**，把 DETR 换成 **FCOS 式密集头**（每位置密集监督，~4.9万位置 vs 300 query），
同一冻结 base、同一 1504 集、同一 recall@0.5 口径再跑过拟合。

**结果（FCOS train recall top300 曲线，level L1）**：
`1k:54% → 2k:76% → 3k:91% → 4k:96% → 5k:96.5% → 6k:97.3%`，val top300 稳在 ~51–56%，**全程不坍塌**。

| 同一冻结特征 + 同一 1504 集 | train recall 峰值 | val recall | step6000 行为 |
|---|---|---|---|
| DETR 头（D1） | **~20%** | ~17% | **坍塌→3.5%** |
| **FCOS 头（D1'）** | **97%** | ~52–56% | **稳定无坍塌** |

**翻案结论**：

- **B 被推翻**：冻结 DINOv2 + 深度锚定共享 Adapter 的特征**完全够用**——能撑到 **97% train recall**。
  之前的 ~20% 天花板**全是 DETR 头（稀疏query+匈牙利匹配+过训坍塌）的锅，不是特征**。**无需私有 adapter / LoRA**（D2 取消）。
- **真正剩下的瓶颈 = A（数据 / 泛化）**：train 97% vs val ~52% 的剪刀差是教科书式过拟合——1354 图不够泛化，
  但特征+头有能力。解法是**扩穷尽标注数据**（COCO train2017 全量已下 18GB + Objects365）。
- **C（坍塌）= DETR 专属病**：FCOS 在 DETR 的坍塌点（step6000）纹丝不动，证明坍塌是 DETR 训练动力学问题，换头即免疫。
- **低置信（conf p99≈0.3）链条**：DETR softmax-over-queries 的低置信本就是 DETR 特性；FCOS 用 per-class sigmoid+focal，
  置信语义不同，应在新头上重新评估 conf（注意 D1' 的 p99 是 cls×ctr 双 sigmoid 之积，天然偏低，需单独标定）。

**新主线（取代原 §4 的 B/C 分支）**：
1. **FCOS 扶正为检测头**（替换 DETR），代码已落地：`fcos_head.py / fcos_loss.py / fcos_model.py / train_fcos.py`，
   `checkpoints/fcos_d1/best.pt`（step5000, val top300 0.53 / train 0.96）。
2. **重开 A 路**：扩 COCO 全量 + Objects365 穷尽标注；LVIS 非穷尽用 federated loss。预期 val 随数据量抬升（当前 ~52% 是 1354 图的泛化上限）。
3. 目标口径迁移：把 top300 / thr05 诊断口径过渡到 §6 的 recall@conf0.5 / Top-50 验收线（需先标定 FCOS 置信度）。

### 3.7 生产化战线实测（2026-06-08/09，FCOS→A路→QFL→标定→FP→DFL）

> **口径修正（重要）**：`conf0.05` / `top300` 是诊断期口径，**实际部署不可用**（保留数百框）。
> **本节及以后只认 `recall@conf0.5`（标定后）作可部署指标**；此前一切 0.05 / top300 数字**仅作能力上限参考、不作验收**。

**A 路（扩数据）**：COCO **train2017 35326 穷尽图**训练 → val2017(1504) held-out。结果 train≈val（**真泛化非记忆**），证实数据有效、容量充足。

**置信度战线（核心障碍：高置信高召回）**：

| 阶段 | recall@conf0.5（可部署口径） | 说明 |
|---|---|---|
| DETR 头 | **≈0** | 分数从不到 0.5 + 坍塌 |
| FCOS + focal+centerness | **≈0** | TP 分数 frac>0.5=0（focal 系统性压低，诊断：TP cls p50=0.12，centerness 0.77 非元凶） |
| FCOS + **QFL**（cls目标=IoU，去centerness） | raw **13%** | TP 分数 p50 0.12→0.245 |
| FCOS + QFL + **Platt 标定** | **26%** | 当前最佳可部署数；标定使 conf0.5≈"50%可能正确" |
| FCOS + QFL + **DFL** | raw 升至 ~10-15%（未训熟即停） | @容量提升，标定后未测 |

**FP 成分诊断（精度=真瓶颈）**：在 conf0.5 可部署口径下，假阳主要是 **定位差 FP_loc 47%**（IoU 0.1-0.5，差一点）+ **背景幻觉 FP_bg 39%**；NMS漏8.7%、类别错5.2%次要。→ DFL 攻定位为对症之举。

**当前诚实现状**：可部署 **recall@conf0.5 ≈ 26%**，距 §6 的 70% 线仍远。**瓶颈已从"召回容量"转为"高置信精度"。**

### 3.8 重新打开的 B 假设（精度层面）—— 下一步 D2

D1' 当初推翻的 B 是**容量层面**（特征能"找到"物体，train 97%）。但**高置信精度层面的 B 仍是开放问题**：冻结自监督特征可能不足以支撑"自信判别 TP/FP + 紧框 + 拒背景"，这与 FP_loc/FP_bg 高度一致。

**D2（正面验证"冻结后端是否为精度主因"）**：给冻结 backbone 配**检测私有可训练 adapter**（首选，已批准、不动共享基座、保无损合并）或 **LoRA 末层**，与 FCOS 头联合训练、backbone 仍冻结。判读：标定后 recall@conf0.5 若显著超 26% → 冻结后端是精度主因实锤；若无改善 → 瓶颈在别处（数据/架构/任务），需换思路。详见独立 D2 计划。

## 4. 第二步：按诊断结论对症

| 诊断主因 | 对症动作 | 牵动范围 |
|---|---|---|
| **A 数据** | 扩 COCO train2017 全量（已下载 18GB）+ Objects365 映射，**穷尽标注优先**；federated loss 处理 LVIS 漏标长尾 | 仅数据 pipeline |
| **B 特征 / Adapter 锚定** | 给检测头配**轻量私有 adapter**（已批准，检测专属、**不动**已冻结的共享基座与深度头）；或 LoRA 末层——取 D2 中性价比高者 | 仅检测头分支 |
| **C 动力学** | DN-DETR / DINO **denoising query** 稳定匈牙利匹配、抗过训坍塌；EMA；**focal / objectness 权重重配**解低置信；short schedule + best.pt 固化；query 数（Nq≈300）调优 | 仅检测头训练配置 |

> **C 战线可立即并行启动，不必等诊断**：过训坍塌（26→6%）与 conf p99≈0.3 是**确定性病灶**，不依赖归因。建议 C 与 D0–D3 **同时开跑**，先把训练稳定性的唾手可得收益拿到手。

## 5. 范围边界（本轮铁律）

- **只动检测头**：深度 / 分割 / 房间本轮不碰。
- **共享 Adapter 与深度头不重训**：根源（B）若成立，用**检测私有 adapter** 兜底，**不牵动全局**、不破坏其他头与"无损合并"前提（08 文档 §8.1 版本钉死约束）。
- **数据规模混淆变量优先消除**：任何"冻结 vs 松动"结论都必须在排除"2 万图 vs 起步 10–30 万"这一量级差之后才可信。

## 7. 下一轮备忘（本轮不做，存档）

讨论中识别、但本轮明确不展开的其余三头优化思路：

- **房间头（Stage3，真实基线 scene-disjoint 72.2%）**：
  - 隐形杀手是 **GAP**——`CLS + GAP(P4/P5)` 把 laundry/entryway 赖以判别的**局部线索**（洗衣机、门廊鞋柜）糊掉。换 **attention pooling** 性价比最高；
  - 类不均衡：class-balanced / LDAM / logit-adjustment loss + 弱类重采样；补 HM3D / Matterport3D 的弱类样本（ScanNet 这些类太少）；
  - 评估时区分"核心类"与"过渡类"，过渡区允许 soft / 低置信。
- **分割头（Stage2，IoU 0.71）**：
  - **先量化**"边缘松 → mask 内深度中位数 → 物体 3D 位置误差"的实际影响，确认值得做再做（下游取中位数对边缘松天然鲁棒，可能已够用）；
  - 真要提：boundary-aware loss / 更高分辨率线索 / PointRend 式精修 / SAM 边缘蒸馏。
- **深度头（Stage0，已达标 AbsRel 0.056 / δ1 0.966）**：
  - 自身无需优化；真正议题是**共享 Adapter 是否为语义任务重训/加私有分支**——已决定本轮用检测私有 adapter 兜底，不重训共享基座。
